# 旧《晨光中国》迁移建议

## 可访问的旧项目快照

已发现 `C:\Users\HUAWEI\Downloads\morning-china-0.2.1.zip`。它是 TypeScript/Vite 原型，包含 `astronomy-engine@2.1.19`、`suncalc@2.0.1`、代表城市数据、SVG 原型地图、时间轴和太阳计算测试。当前工作区没有旧项目展开目录，迁移应以快照为只读参考，不直接在其上改造。

## 建议复用

- `src/domain/solar.ts` 的纯函数边界：北京时间日期校验、太阳赤经/赤纬状态、太阳高度角/方位角、曙光/日出/日落、四季瞬时。
- `test/solar.test.mjs` 的验证样例：单点与中国范围格网场公式误差、四季顺序、与 SunCalc 的事件交叉核验、无日出/日落 null 语义。
- `src/data/places.ts` 的城市数据结构和首批代表城市候选；坐标、名称和来源需重新核验并加入 `source` 字段。
- 播放状态中分钟、速率、循环、主/对比 slot 的产品语义。

## 不应继承

- `@svg-maps/china` 作为最终地图几何。旧项目自己声明它只是原型，且来源为 MapSVG CC BY 4.0，不能替代用户提供的官方 EPS。
- `src/main.ts` 约 826 行的单体模板、事件绑定和硬编码 `mapBounds`；应拆成地图、天文、动态场、交互和 UI 层。
- 旧项目中的合成 relief band、river line、线性经纬映射和近似地图背景；它们可作为视觉实验记录，不是官方地形/边界事实。
- 旧项目的固定 2026 四季日期、界面文案和竞赛说明文字；新项目应由日期/节气模型和设计规格驱动。

## 迁移顺序

1. 从只读快照提取并隔离 `solar.ts` 与测试，确认依赖许可证。
2. 建立官方地图 manifest、投影/控制点和 SVG/GeoJSON 派生资产。
3. 把 `Place`、`SolarState`、`MorningEvents` 迁移到独立 domain 包，补充来源和坐标基准。
4. 新建 `LightFieldRenderer`，先用纯色场替代旧的合成 relief，再接入 DEM。
5. 按参考图重做地图主舞台、右轨和底部时间轴，保持状态单向流动。
6. 加入截图回归、几何不变性检查、性能基准和无障碍测试。

## 需要避免的技术债

- 不让 UI 组件直接调用天文库或读写地图路径。
- 不在多个地方重复计算时区、经纬度映射和事件格式化。
- 不把数据来源、许可和审图信息写死在展示文案中。
- 不以第三方地图包或参考图像的视觉相似度替代官方几何验收。
- 不在没有性能证据时引入 WebGL、3D 地球或实时云层。

## 迁移验收

- 太阳算法新旧结果在测试样本上相同或差异有解释。
- 官方地图替换后，城市点、经纬网和动态场仍通过同一投影接口对齐。
- 删除旧原型地图包后，项目仍能从 manifest 加载合规资产。
- 旧项目单体页面不被复制；所有核心状态均可被纯函数测试覆盖。
