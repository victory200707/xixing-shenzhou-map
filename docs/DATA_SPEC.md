# 数据需求与科学模型

## 数据分类总表

### 必须由用户提供或确认

| 数据 | 原因 | 当前状态 |
| --- | --- | --- |
| 最终官方中国地图版本（EPS 及来源证明） | 决定所有地理事实 | 已发现三份候选，尚未确认最终版 |
| 审图号/公开发布许可/署名要求 | 决定能否发布 | 未提供，必须确认 |
| 旧《晨光中国》仓库或允许迁移的版本 | 复用已验证算法与测试 | 已发现 `morning-china-0.2.1.zip`，需确认其为可迁移版本 |
| 品牌标题字稿/字体要求（若必须与参考图一致） | 决定标题资产 | 未提供，可先用授权字体占位 |

### 可通过公开可靠来源获取

| 数据 | 推荐来源与格式 | 精度/许可注意 |
| --- | --- | --- |
| DEM | Copernicus DEM GLO-30 或 NASADEM/SRTM 30 m GeoTIFF | 先核对对中国境内使用、派生图像发布和再分发条款；产品首屏可重采样至约 0.5–2 km 栅格 |
| 城市坐标与标准名称 | 自然资源主管部门/天地图等官方服务；必要时用 GeoNames 做交叉核验 | 记录查询日期、坐标基准和 API 条款；首批城市点 0.01° 级足够，正式名单需用户确认 |
| 行政名称/代码（如需） | 民政部行政区划公开信息或官方地图属性 | 不从第三方 SVG 反推边界；名称版本需锁定 |
| 天文库 | 项目依赖 `astronomy-engine`；`suncalc` 作为独立交叉核验 | 库许可证需进入第三方声明 |

### 可由程序实时计算

- 北京时间日期与 UTC 瞬时（中国统一 `Asia/Shanghai`, UTC+8）。
- 太阳赤经、赤纬、格林尼治恒星时。
- 任意地图格网点的太阳几何高度角、方位角。
- 天文/航海/民用曙光、理论日出、日落和阶段分类。
- 昼夜/晨昏分界线、城市在当前时间的阶段与颜色。
- 春分、夏至、秋分、冬至的瞬时和节气预设。
- 主/对比城市的日出差、曙光差、当地太阳时等派生指标。

### 可由程序生成

- 固定随机种子的星点、微弱噪声和背景纹理。
- DEM hillshade 的色调、阴影、晨光渐变、边界光晕和玻璃面板效果。
- 低分辨率动态光场缓存、图例色带和城市高亮环。

## 科学定义与假设

- 默认时间基准为北京时间；所有内部状态用 UTC `Date` 或等价 epoch 表示，展示时再格式化为北京时间。
- 理论日出沿用旧项目的太阳中心几何高度约 `-0.833°`（太阳半径与标准折射近似）；文案必须标注“理论日出”，除非引入经核验的地形/大气模型。
- 晨光阶段阈值：天文曙光 -18°、航海曙光 -12°、民用曙光 -6°，日出事件 -0.833°；连续颜色和阶段分类共享同一高度角。
- 地图场可用单一太阳赤经/赤纬状态在中国格网中计算；旧项目已用独立点计算验证误差目标 ≤0.01°。
- DEM 默认只用于地形质感，不改变理论日出；真实地形遮挡是后续可选科学模块。
- 极端高纬地区可能出现无日出/无日落，接口必须允许 `null` 并在 UI 中解释。

## 推荐数据结构

```ts
type SolarState = {
  instantUtc: string;
  rightAscensionHours: number;
  declinationDeg: number;
  greenwichSiderealHours: number;
};

type MorningEvents = {
  astronomicalDawn: string | null;
  nauticalDawn: string | null;
  civilDawn: string | null;
  sunrise: string | null;
  sunset: string | null;
};

type Place = {
  id: string;
  name: string;
  region?: string;
  latitude: number;
  longitude: number;
  elevationMeters?: number;
  source: string;
};
```

## 验证与可重复性

- 复用旧项目 `solar.ts` 的输入校验、北京时间日期解析、场公式和事件计算。
- 继续用 `suncalc` 对四季、代表城市的日出/日落/曙光交叉核验，目标差异不超过 1 分钟；记录时区和 null 情况。
- 对地图场在春分、夏至、秋分、冬至及中国范围格网做误差回归测试。
- 太阳场、DEM 派生图和城市投影都应可由固定输入和版本化脚本重建。

## 不应提前制作的数据表

太阳位置、太阳高度角、晨光阶段、分界线、日出/日落和节气瞬时应由算法实时计算；只有在性能测试证明必要时，才为固定日期/分辨率建立可校验缓存。
