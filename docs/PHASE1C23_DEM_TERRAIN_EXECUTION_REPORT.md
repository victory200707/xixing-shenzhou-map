# Phase 1C-23: DEM 地形起伏执行报告

## 1. 决策

当前 JPG 视觉纹理方案已经完成验证，但实际页面中地形起伏不可见，继续调整透明度无法恢复原始地形结构。因此本阶段转向 DEM Hillshade 方案。本次实际采用公开 AWS `elevation-tiles-prod` Terrarium 高程瓦片生成离线 Hillshade；它是 DEM 视觉派生层，不是新的地图底图。

DEM 只用于离线生成地形明暗纹理，不替换官方底图，不修改国界、省界、海岸线、城市或南海 inset。

## 2. 目标

- 在中国大陆、海南、台湾陆地内部呈现可见的山脉和高原起伏；
- 白昼暖金、晨昏蓝紫到暗金、夜面深蓝的太阳色彩仍保持动态；
- 地形纹理与当前网站地图完全共用同一显示坐标和视觉 Mask；
- 西藏南部、海南、台湾不出现缺口或错位；
- 海域、背景、南海 inset 和右侧 UI 不被地形纹理覆盖；
- 官方 SVG/EPS 和天文计算链保持不变。

## 3. 技术流程

```text
公开 AWS `elevation-tiles-prod` Terrarium 高程瓦片（上游 DEM）
→ 拼接覆盖中国大陆、海南、台湾的瓦片
→ WGS84 高程栅格
→ 项目 LCC 投影
→ SpatialBridge / SVG V 坐标配准
→ 计算 Hillshade
→ 明暗归一化和蓝灰色视觉映射
→ 当前网站同源陆地 Mask 裁切
→ 独立地形 Canvas
→ 太阳冷暖层
→ 官方 SVG、城市和文字
```

## 4. 图层结构

`背景 → DEM 地形层 × 同源视觉 Mask → 太阳颜色层 × 同源视觉 Mask → 官方主图 SVG → 南海 inset → 城市 → UI`

地形层只改变明暗；太阳层只改变冷暖和昼夜状态。两者不能合并成一张覆盖式渐变。

## 5. 由 Codex 完成

1. 检查 DEM 瓦片的覆盖范围、编码、来源和许可说明。
2. 拼接和裁剪 DEM 瓦片，保留原始文件和 SHA-256。
3. 按项目现有 LCC 和 SpatialBridge 转换到 SVG V 坐标。
4. 计算 Hillshade，并生成适合网页显示的高分辨率纹理。
5. 使用当前网站同源视觉 Mask 裁切地形层。
6. 将地形层从太阳光场中独立出来，清除旧的 JPG 和径向渐变占位。
7. 保持 UTC、WGS84、太阳高度角、晨昏阈值和城市计算不变。
8. 在 05:00、06:00、08:00 BJT 及宽屏尺寸下进行截图、控制台和边界验收。
9. 更新 `docs/`、元数据、来源、处理参数和限制说明。

## 6. 必须由用户完成

### 必须项

1. 确认公开 Terrarium 瓦片的上游许可和署名要求可用于最终发布。
2. 若要求正式高程来源，再提供或授权 Copernicus DEM GLO-30 / SRTM 30m 的正式数据和许可信息。
3. 在最终截图上确认地形视觉效果是否达到参考图要求。

### 非必须项

- 不需要重新制作官方地图；
- 不需要手工绘制中国轮廓；
- 不需要修改 SVG/EPS；
- 不需要编写太阳公式；
- 不需要在浏览器中实时加载 DEM；
- 不需要安装 GIS 软件，若当前环境无法处理，我会使用离线栅格处理链替代。

## 7. 关键风险

- DEM 海岸线和官方制图边界可能不完全一致，因此 DEM 不能直接作为地图边界，必须经过当前同源 Mask 裁切。
- 30m DEM 数据量较大，浏览器不应逐像素实时计算；应预先生成 Hillshade PNG 或同等栅格资产。
- DEM 可以解决“没有地形起伏”的问题，但不能单独解决光照错位；坐标链和 Mask 仍是贴合的关键。
- 本阶段生成的 Hillshade 是地形视觉层，不应替代正式地图数据。

## 8. 验收标准

- 05:00：东部开始出现暖色，西部保持冷色，同时能看到山脉起伏；
- 06:00：昼面向西推进，地形纹理连续；
- 08:00：中国大陆主体为暖金色，但山脉和高原明暗仍可辨认；
- 西藏南部无缺口；
- 海南和台湾有完整地形纹理；
- 海域、背景和南海 inset 不被染亮；
- 官方边界、城市名称和省界清晰；
- 无矩形、梯形、硬边或错位；
- 控制台 `error/warn` 为 0。

本项目不需要从头重做地图。最小改动路径是：保留现有地图、坐标和太阳计算，替换地形纹理生成方式，并使用同源 Mask 进行裁切。
